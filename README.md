### 管理画面の安全な使用方法

1. `admin.html` を開く前にGitHubの現在の `data/` を確認します。
2. 管理画面で「元データをバックアップ」を押します。
3. 出典・公演情報などを編集します。複数出典、開演時刻、放送局、追加フィールドは保持されます。
4. 「更新用3ファイルZIPを保存」を押し、ZIP内の `data/events.json`・`data/events.js`・`data/events.csv` を確認します。
5. GitHubの `data/` 内の**同名3ファイルをセットで**アップロードしてCommitします。
6. 更新後に件数・個別記録・出典リンクを確認します。

管理画面はGitHubへ直接書き込みません。ブラウザー内での編集は再読み込みで失われるため、作業途中のJSON控えを保存してください。「JSONを読み込む」は全記録を置き換える操作なので、バックアップ後に使用してください。

**重要：`data/events.json` が正本です。** CSVのみで過去データの全項目を復元することはできません。管理画面が出力するCSVは照合用です。

### 編集・照合の原則

- 同日・同会場でも昼夜別公演など別の出来事は別IDを保持します。
- `postponed`（延期）、`cancelled` / `canceled`（中止）を公演実施済みとして扱いません。
- `scheduled`（開催予定）は日付が経過しても自動で「開催済み」に断定せず、実施確認を待ちます。
- `verification: primary` は公式などの一次資料で確認できたもの、`secondary` は二次資料に基づくものとして区別します。
- 出典URLとIDを維持し、根拠なく削除・上書きしません。
- 開催日と放送日、発売日を区別し、日付不明の出来事を推測で登録しません。
- 「記録・記念日」と「デビュー前・アマチュア活動」は別分類です。
- Chage・ASKAの誕生日、8月25日のデビュー周年は画面上で自動表示し、毎年の記録を機械的には増やしません。
